<objective>
Close the critical and warning findings from `08-REVIEW.md` / `08-VERIFICATION.md` against the shipped approval gate: the attestation chain (CR-01 + WR-01) and the accountability defects (WR-02, WR-03, WR-04, WR-05, plus the IN-01/IN-03/IN-04 hygiene items).

Purpose: today `approve_module()` rewrites `manifest.json`, which is inside the hashed bundle the installer verifies — so an attested install of a legitimately approved module ALWAYS fails, while the default (unattested) install path performs no integrity check at all. The phase's own done criterion ("no module installed without explicit user approval") therefore reduces to "a status flag was flipped." This plan binds the approved artifact to the installed artifact cryptographically.
Output: a code-only bundle hash helper, an `approved_bundle_sha256` manifest field issued at approval, unconditional install-time verification, individual-admin audit attribution, and a regression test that runs the real validate → approve → install chain.
</objective>
