<objective>
Extend the 2-second pipeline SSE payload so modules that exist on disk but were never loaded (VALIDATING / VALIDATED / APPROVED / FAILED) are visible to the pipeline graph, each carrying explicit `status`, `pending_approval`, and `build_stage` fields.

Purpose: D-04 says "the graph is the notification" — but today `_build_pipeline_state()` sources modules exclusively from `loader.list_modules()`, which only knows *loaded* modules, so a VALIDATED module awaiting approval is invisible. This is a backend gap, not a UI gap (RESEARCH Pattern 3). D-03 makes SSE the transport, and the Phase 6 rule is that the UI renders only from backend contracts — approval state must arrive in the payload, never be inferred client-side.
Output: a `_build_pending_approval_list()` helper merged into the existing payload, plus unit tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MODULES_DIR on disk → SSE payload → browser | untrusted, LLM-generated manifest content is serialized to every connected UI client |
| unauthenticated SSE endpoint → module inventory | `/stream/pipeline-state` is in dashboard's `public_paths` (no API key required) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-11 | Information Disclosure | manifest fields streamed to unauthenticated SSE clients | mitigate | Emit only id/name/category/status/pending_approval/build_stage/state — never `api_key_instructions`, credential material, validation error details, or file paths |
| T-08-12 | Denial of Service | `ModuleManifest.discover` rglob every 2s over a large MODULES_DIR | accept | Scan is bounded by the module count in a single mounted volume (tens of dirs); `discover` already tolerates bad files. Revisit with a cache keyed on directory mtime only if a slow-cycle warning appears in logs |
| T-08-13 | Tampering | a crafted manifest.json crashing the stream for all clients | mitigate | Helper is fully wrapped in try/except returning `[]`; `discover` already skips unparseable manifests; unit test covers the malformed case |
</threat_model>
