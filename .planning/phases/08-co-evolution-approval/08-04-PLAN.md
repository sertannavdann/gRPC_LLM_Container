<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GC marker file (attacker-influenced module_id) → filesystem delete | a path in a marker drives `shutil.rmtree` |
| retention worker → billing SQLite | a background process issues unattended DELETEs |
| retention worker → audit stores | a background process runs next to tamper-evident records it must not touch |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-14 | Destruction of data | `purge_module_artifacts` path handling | mitigate | Resolve every delete target with `Path.resolve()` and assert it is inside the resolved `modules_dir`/`artifacts_dir` before `rmtree`; reject `..` traversal in `module_id`; never delete `*.db` or `*.jsonl` |
| T-08-15 | Destruction of data | audit trail deleted by GC | mitigate | Audit is GC-exempt (07-CONTEXT D-01): the worker never opens `AUDIT_DB_PATH`, never scans `AUDIT_DIR`, and preserves `*.jsonl` found inside purged module dirs (Task 1 test asserts this) |
| T-08-16 | Destruction of data | rollback pointer target deleted | mitigate | D-12 reference-safety check against `active_versions` before every delete (Task 1) |
| T-08-17 | Tampering | SQL injection through org_id into retention DELETE | mitigate | Parameterized `DELETE ... WHERE org_id = ? AND created_at < ?` only (Task 2 acceptance criterion) |
| T-08-18 | Denial of Service | unbounded sweep blocking the event loop | accept | Sweep runs in its own daemon thread on a daily interval over a bounded module tree; each module is individually try/except-wrapped. Revisit with batching if pass duration is logged above one minute |
</threat_model>
