## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| any HTTP client → dashboard (:8001) / admin (:8003) | unauthenticated and authenticated traffic, including credential-guessing attempts |
| rate-limit bucket key ← attacker-controlled X-API-Key header | an attacker chooses their own bucket identity |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-19 | Denial of Service | all HTTP endpoints | mitigate | Token-bucket limiter outermost on both apps with per-prefix rules; 429 + Retry-After (REQ-020) |
| T-08-20 | Elevation of Privilege | API-key brute force against `/admin/bootstrap` and auth | mitigate | Limiter runs BEFORE `APIKeyAuthMiddleware`, and `/admin/bootstrap` gets the strictest rule (0.2 rps, burst 3) |
| T-08-21 | Denial of Service | bucket-key cardinality blowup via rotating X-API-Key headers | accept | In-memory registry grows per distinct header value; this is a per-process dict in a trusted-network deployment with no Redis available. Documented residual risk — bound it with an LRU or key hashing if memory growth is observed |
| T-08-22 | Information Disclosure | raw API keys in throttle logs | mitigate | Log only a fingerprint/prefix of the identity, never the key (Task 1 action) |
| T-08-23 | Repudiation | a mutation slipping through unaudited because of a 429 | mitigate | The limiter short-circuits in middleware before any handler runs, so no partially-applied unaudited mutation is possible; invariant recorded in the wiring comment |
