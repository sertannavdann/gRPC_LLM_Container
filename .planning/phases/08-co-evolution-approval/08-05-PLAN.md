shared/utils/rate_limiter.py — `TokenBucketRateLimiter(rate: float, burst: int, name: str)` with
`acquire_sync(tokens=1) -> bool`, `async acquire(tokens=1) -> bool`, `retry_after(tokens=1) -> float`,
`available_tokens` property, `reset()`. `RateLimiterRegistry.get(provider: str) -> TokenBucketRateLimiter`
(thread-safe, lazily creates a limiter from `DEFAULT_LIMITS`, default `(10.0, 20)` for unknown names).
Module-level `get_rate_limiter_registry() -> RateLimiterRegistry` singleton, plus `RateLimitExceeded`.
NOTE: `RateLimiterRegistry.get()` applies its own provider defaults — this middleware must NOT rely on
those; register explicit limiters via `registry.register(name, rate=..., burst=...)` on first use per bucket.
NOTE 2: the registry is a PROCESS-WIDE singleton, so buckets survive across tests in one pytest process —
bucket keys must be unique per test, or the registry must be cleared between tests.

shared/auth/middleware.py — `APIKeyAuthMiddleware(BaseHTTPMiddleware)` with
`__init__(self, app, api_key_store, public_paths=None)` + `super().__init__(app)`, `async def dispatch(request, call_next)`
that returns early on `request.method == "OPTIONS"`, skips `public_paths` (exact match or `path.startswith(public + "/")`),
reads `request.headers.get("X-API-Key")`, and returns `JSONResponse(status_code=401, content={"detail": ...})`.
`DEFAULT_PUBLIC_PATHS = ["/health", "/admin/health", "/docs", "/openapi.json", "/redoc", "/metrics"]`.
This is the exact class shape to mirror.

Starlette ordering rule (RESEARCH Pitfall 3): `add_middleware()` wraps in REVERSE call order — the LAST
call is the OUTERMOST and runs FIRST. Do not key the limiter off `request.state.user` (it is not set yet
when the limiter is outermost); read the `X-API-Key` header directly.

dashboard_service/main.py — current call order is `add_middleware(AuditContextMiddleware)` (line ~337),
`add_middleware(APIKeyAuthMiddleware, ...)` (line ~339), then `add_middleware(CORSMiddleware, ...)` (line ~361).
So CORS is currently outermost. Insert the rate-limit call BETWEEN the auth call and the CORS call so the
resulting order is CORS → RateLimit → Auth → AuditContext.

orchestrator/admin_api.py — CORS is added at module import (line ~85); `start_admin_server()` adds
`AuditContextMiddleware` (line ~2087) then `APIKeyAuthMiddleware` (line ~2089). Add the rate-limit call

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| any HTTP client → dashboard (:8001) / admin (:8003) | unauthenticated and authenticated traffic, including credential-guessing attempts |
| rate-limit bucket key ← attacker-controlled X-API-Key header | an attacker chooses their own bucket identity |
| deployment environment → RATE_LIMIT_ENABLED | an env var can switch the control off |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-19 | Denial of Service | all HTTP endpoints | mitigate | Token-bucket limiter outermost on both apps with per-prefix rules; 429 + Retry-After (REQ-020) |
| T-08-20 | Elevation of Privilege | API-key brute force against `/admin/bootstrap` and auth | mitigate | Limiter runs BEFORE `APIKeyAuthMiddleware`, and `/admin/bootstrap` gets the strictest rule (0.2 rps, burst 3) |
| T-08-21 | Denial of Service | bucket-key cardinality blowup via rotating X-API-Key headers | accept | In-memory registry grows per distinct header value; this is a per-process dict in a trusted-network deployment with no Redis available. Documented residual risk — bound it with an LRU or key hashing if memory growth is observed |
| T-08-22 | Information Disclosure | raw API keys in throttle logs | mitigate | Log only a fingerprint/prefix of the identity, never the key (Task 1 action) |
| T-08-23 | Repudiation | a mutation slipping through unaudited because of a 429 | mitigate | The limiter short-circuits in middleware before any handler runs, so no partially-applied unaudited mutation is possible; invariant recorded in the wiring comment |
| T-08-59 | Denial of Service | rate limiting silently switched off in production via `RATE_LIMIT_ENABLED` | mitigate | The switch is default-ON (absent env var = enabled), requires an explicit falsey value, and logs a WARNING at construction whenever it is disabled so a misconfigured deployment is visible in logs. It is set to false only inside `tests/integration/admin/conftest.py` |
</threat_model>
