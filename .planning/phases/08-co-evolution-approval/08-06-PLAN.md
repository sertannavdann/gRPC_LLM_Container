<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM-generated adapter source → LLM prompt | untrusted generated code is fed back into a model as input |
| LLM-generated prose → manifest.json → review UI | model output is persisted and later rendered to an admin |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-24 | Tampering | prompt injection embedded in adapter.py steering the walkthrough to describe benign behavior | mitigate | The walkthrough is explicitly an aid, never an authorization input: nothing in the approval or install path reads `manifest.walkthrough`. The system prompt frames the source as untrusted data to be described, and the review panel still shows the raw code diff and sandbox report alongside it (D-06) |
| T-08-25 | Information Disclosure | secrets present in adapter source shipped to an external LLM provider | mitigate | Only `adapter.py` (generated code, no credential store access) is sent, truncated to `max_chars`; `.env`, credential DBs, and manifests are not included in the prompt |
| T-08-26 | Denial of Service | walkthrough generation hanging or exhausting budget during validation | mitigate | Runs through `LLMGateway._check_budget` and `_call_provider_with_retry` like every other lane; whole call is try/except-wrapped and returns `""` on any failure so validation always completes |
| T-08-27 | Information Disclosure | model output rendered as markdown in the review panel (script injection) | transfer | Rendering is `react-markdown` (already a dependency, escapes raw HTML by default) — enforced by the display plan 08-09; noted here as a cross-plan dependency |
</threat_model>
