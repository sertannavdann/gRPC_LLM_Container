    Create `ui_service/src/machines/pipelinePage.ts` exporting `pipelinePageMachine`, `PipelinePageContext`, and `PipelinePageEvent`.

    Context: `{ pipeline: PipelineState | null; lastUpdate: number; selectedNodeId: string | null; selectedModuleId: string | null;
    review: ModuleReview | null; audit: ModuleAuditAttempt[]; actionError: string | null }`.

    Events: `{ type: 'SSE_MESSAGE'; data: PipelineState } | { type: 'SSE_ERROR' } | { type: 'SELECT_NODE'; nodeId: string; moduleId?: string }
    | { type: 'CLOSE_PANEL' } | { type: 'APPROVE' } | { type: 'REJECT'; feedback?: string } | { type: 'RETRY' }`.

    Actors (all in `setup({ actors: ... })`):
    - `sseConnection: fromCallback(({ sendBack }) => { const es = connectPipelineSSE((s) => sendBack({ type: 'SSE_MESSAGE', data: s }), () => sendBack({ type: 'SSE_ERROR' })); return () => es.close(); })` — RESEARCH Pattern 4. The returned cleanup closing the EventSource is mandatory; without it every re-entry leaks a connection.
    - `loadReview: fromPromise(async ({ input }) => ...)` calling `adminApi.getModuleReview` and `adminApi.getModuleAudit` for the selected module (split the `moduleId` on `/` into category/platform) and returning both.
    - `approveAction: fromPromise(...)` calling `adminApi.approveModule`; `rejectAction: fromPromise(...)` calling `adminApi.rejectModule` with the event's optional feedback.

    Machine: `type: 'parallel'` with three regions.
    1. `connection`: `connecting` (invokes `sseConnection`, `on: { SSE_MESSAGE: { target: 'connected', actions: 'updatePipeline' } }`) → `connected` (`on: { SSE_MESSAGE: { actions: 'updatePipeline' }, SSE_ERROR: 'reconnecting' }`) → `reconnecting` (`on: { SSE_MESSAGE: { target: 'connected', actions: 'updatePipeline' } }`). The `sseConnection` actor must be invoked at the REGION level (or on a wrapping state) so it is not torn down and recreated on every `connecting → connected` transition — native EventSource already auto-retries, so the actor stays alive across `reconnecting`.
    2. `selection`: `none` (`on: { SELECT_NODE: { target: 'selected', actions: 'setSelection' } }`) → `selected` (`on: { SELECT_NODE: { actions: 'setSelection' }, CLOSE_PANEL: { target: 'none', actions: 'clearSelection' } }`).
    3. `reviewPanel`: `closed` → `loading` (invokes `loadReview`, onDone → `open` storing review+audit, onError → `error`) → `open` (`on: { APPROVE: 'approving', REJECT: 'rejecting', CLOSE_PANEL: 'closed' }`) → `approving` / `rejecting` (invoke the corresponding action actor; onDone → `closed` with cleared selection, onError → `error` storing `actionError`) → `error` (`on: { RETRY: 'loading', CLOSE_PANEL: 'closed' }`). Entering `loading` is triggered by a `SELECT_NODE` event that carries a `moduleId`; a `SELECT_NODE` without a `moduleId` (a stage/tool/adapter node) must leave `reviewPanel` in `closed`— express that with a `guard` named `hasModuleId`.

    Actions defined in `setup({ actions: ... })` using `assign`: `updatePipeline`, `setSelection`, `clearSelection`, `storeReview`, `storeActionError`. No `console.log`. No direct `fetch` — everything goes through `adminApi`. Keep every state exclusive (no two simultaneous action states on one module) so the UI-SPEC's "never overlap two build-state animations" rule is structurally enforced.
  </action>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-28 | Elevation of Privilege | approve/reject issued from the browser | transfer | Authorization is enforced server-side by `require_permission(Permission.WRITE_CONFIG)` (D-17, shipped in 08-01). The client must not gate on any client-side role guess; a 403 surfaces as `actionError` and the panel enters `error` |
| T-08-29 | Spoofing | SSE payload asserting approval state | mitigate | The machine treats `pending_approval` purely as a display signal; the actual transition is a server round-trip whose response (`new_status`) is authoritative |
| T-08-30 | Information Disclosure | review payload (walkthrough, credential names) cached in machine context | accept | Same data the operator+ review endpoint already returns; no raw secrets are in the payload (only `requires_api_key`/`auth_type`/instructions). Context is cleared on `CLOSE_PANEL` via `clearSelection` |
| T-08-31 | Denial of Service | leaked EventSource connections on repeated navigation | mitigate | `fromCallback` cleanup closes the EventSource on region exit (acceptance criterion) |
