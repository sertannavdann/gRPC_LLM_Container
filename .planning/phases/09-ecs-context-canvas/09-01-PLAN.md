    Create `ui_service/src/ecs/types.ts` with `'use client'` as its first line (Pitfall 1 — every file
    in `src/ecs/` carries its own directive; do not rely on page.tsx's).

    Export the runtime vocabulary as `as const` arrays plus derived types:
    `KINDS = ['adapter','module','service','stage','tool']`,
    `STATUSES = ['unknown','running','degraded','disabled','error','failed','stopped','building','validating','available']`,
    `LIFECYCLES = ['discovered','installed','pending','validating','approved','rejected','enabled','disabled','error']`.
    Types `Kind`, `Status`, `Lifecycle` derive from those arrays via `(typeof KINDS)[number]`.

    Export `interface EntityRecord` — the full ECS entity, including UI-only fields, because
    snapshots capture full records (locked decision D9-13):
    `id: string`, `label: string`, `kind: Kind`, `status: Status`, `lifecycle: Lifecycle | null`,
    `detail: string | null`, `latency: number | null`, `creds: string[]`, `flags: string[]`,
    `x: number`, `y: number`.

    Export `type CanvasView = Omit<EntityRecord,'x'|'y'>` — the c_state projection. `x`/`y` are
    deliberately EXCLUDED from c_state: they are user-owned drag state, and including them would
    break the "byte-stable across churn for unchanged worlds" Done Criterion the moment a node is
    dragged. Snapshots (history) still carry them; the verbalizer does not.

    Export `entityIdFor(kind: Kind, key: string): string` producing exactly the ids page.tsx already
    uses: service -> `svc-${key}`, tool -> `tool-${key}`, adapter -> `adapter-${key}`,
    module -> `module-${key}`, stage -> `stage-${key}`.

    Add a top-of-file doc comment declaring the C_STATE DSL GRAMMAR that plan 02 (Python port) and
    plan 03 (TS verbalizer) both implement verbatim — this comment is the contract, not decoration:
      header line: `# pipeline_state — line format: <id> "<label>" <status>[/<lifecycle>][ detail=<detail>][ latency=<ms>][ creds:<c1,c2>][ flags:<f1,f2>]`
      then, for each kind in ascending kind order: a `[<kind>]` group header, then one line per
      entity in ascending logical-id order. Optional segments are omitted entirely when the value is
      null or the array is empty. `latency` is rendered as a rounded integer on BOTH sides
      (`Math.round(v)` in TS, `round(v)` in Python) so the two ports cannot diverge on float
      formatting. Labels are wrapped in double quotes with any embedded `"` stripped.

    Create `ui_service/src/ecs/__tests__/types.test.ts` importing `describe`/`it`/`expect` from
    `vitest`: assert `entityIdFor('service','orchestrator') === 'svc-orchestrator'` and
    `entityIdFor('module','weather/openweather') === 'module-weather/openweather'`; assert `KINDS` is
    sorted ascending (the verbalizer relies on kind ordering); assert `STATUSES` contains every
    `state` value the production `ServiceState`/`ModuleState`/`AdapterState` unions can produce
    (`running`, `error`, `idle` -> map `idle` to `unknown` is NOT allowed here; add `idle` to STATUSES
    instead if the union requires it — the test must reflect reality, not aspiration).
  </action>
