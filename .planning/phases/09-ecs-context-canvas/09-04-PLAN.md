<objective>
Build the single mediation path: the SSE sync writer and the LLM staged-proposal writer sharing one
world, one dirty tracker, and one validation function.

Purpose: spike 007 proved that a second writer or a second world is where correctness dies. The
ownership allow-list (LLM ops may touch module entities; services/stages stay read-only except for
`move`/`set_status`) plus re-validation at three points is the phase's entire access-control story
(ASVS V4) and its entire input-validation story (ASVS V5, zod). Both are locked decisions.

Output: `src/ecs/mediation.ts`, `src/ecs/sync.ts`, and the mediation unit suite.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM output -> mediation layer | Fully untrusted structured input; may be malformed, forged, or target entities it does not own |
| SSE snapshot -> ECS world | Authoritative for entity existence; the only source of mirrored-field truth |
| staged proposal -> live world | Crossed only by an explicit human approval action |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Elevation of Privilege | `mediation.ts` op targeting a non-owned entity kind (e.g. `set_credentials` on a service) | mitigate | `OWNERSHIP` allow-list checked against the LIVE world's `target.kind` in `validateOp`, enforced at propose, at every `syncRecords`, and at `approve`. Never bypassed for a "trusted" caller. Asserted by the OWNERSHIP cases in `mediation.test.ts` |
| T-09-02 | Tampering | Stale-proposal race — target removed between staging and approval | mitigate | Re-validation point 2 (`revalidateStagedProposals` inside `syncRecords`, same transition as the removal) plus re-validation point 3 (`approve` re-validates against the live world). Asserted by both the sync-invalidation and non-sync-race tests |
| T-09-05 | Tampering / Input Validation | Malformed or unknown-shaped LLM op | mitigate | `z.discriminatedUnion` with `.strict()` object schemas; structured errors from `result.error.issues`; unknown ops and extra fields refused before any referential check runs |
| T-09-11 | Spoofing | A second writer path bypassing mediation (a component calling `world.add` directly) | mitigate | Single-mediation-path contract documented in `sync.ts`/`mediation.ts` headers and grep-gated in this plan's acceptance criteria (`world.add|world.remove` count is 0 in both files) |
| T-09-03 | Denial of Service (UX) | Optimistic `add_module` desyncing the UI from backend state | transfer | Handled by the pending-confirmation grace in plan 08; `approve()` here only records the world mutation, it does not assume backend persistence |
</threat_model>
