<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| snapshot JSON -> live world | Restoring re-materializes entity records; a corrupted snapshot would corrupt world state |
| event log -> mediation layer | Replay re-executes recorded LLM ops |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-12 | Tampering | In-place restore over a drifted world duplicating entities | mitigate | `restoreSnapshot` clears every entity before re-adding (spike 005a's proven failure mode); asserted by the id-uniqueness test |
| T-09-13 | Elevation of Privilege | Replay re-applying an op that would now violate the ownership policy | mitigate | `replayEvents` re-runs ops through `m.propose` + `m.approve`, so the full zod + `OWNERSHIP` re-validation applies to replayed ops exactly as to fresh ones; divergence throws rather than silently applying |
| T-09-10 | Denial of Service | Unbounded event-log/snapshot growth over a long session | mitigate | Ring bounded by `capacity`; `recordSync` drops the log prefix older than the oldest surviving ring entry; asserted by the ring-bounding test |
| T-09-06 | Information Disclosure | Snapshots holding credential material | mitigate | Snapshots serialize `EntityRecord`s whose `creds` field carries credential NAMES only (never values), consistent with plan 01's contract; history stays in-memory, page-lifetime scoped, never persisted |
</threat_model>
