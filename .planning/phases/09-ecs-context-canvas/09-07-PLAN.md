<objective>
Re-plumb the pipeline canvas onto the ECS world using the buffered React Flow pattern, and prove it
survives real SSE churn with a Playwright spec.

Purpose: this is the highest-risk change in the phase. Spike 001 confirmed that deriving React
Flow's `nodes` prop fresh from `world.entities.map()` on every `touch()` does not degrade rendering
— it BREAKS it outright (blank canvas, ~2700-4900 renders/node/sec, broken even at rest). The
buffered pattern (React Flow owns `nodes` via `useNodesState`; ECS patches non-positional fields by
id; position writes back on drag-stop only) is mandatory and non-negotiable.

Output: extracted pure layout builder + its unit test, the rewired page, and the churn E2E spec.
</objective>

|----------|-------------|

| user drag gesture -> ECS entity position | The only user-owned write into the ECS world |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-16 | Denial of Service (self-inflicted) | Fresh-array derivation of `nodes` from the ECS on every `touch()` | mitigate | Buffered patch-by-id effect; grep-gated (`world.entities` count is 0 in page.tsx); spike 001 measured this as a hard rendering break, not a slowdown |
| T-09-17 | Tampering | Drag-stop write-back to an entity removed mid-drag by an intervening SSE sync | accept (documented) | `if (n && entity)` existence guard is the full extent of spike-tested protection (09-RESEARCH.md A4/Pitfall 3, explicitly unverified); flagged in code and slated for the plan-10 manual verification rather than speculative machinery |
| T-09-18 | Tampering | Every entity tagged as user-touched because `onNodesChange` loops the whole array | mitigate | Only the `NodeChange` entries with `type === 'position'` and a matching id are written back — the exact spike bug called out in the skill blueprint's What-to-Avoid |
